Use it to derive many keys from one master key kept on the token, separated by label (the purpose) and
context (the party, tenant or session).

**What differs from `SP800108HmacCounterKdf`:**

- The master key is a token key that may derive (`CKA_DERIVE`). `DeriveKey(label, context, template)`
  creates each derived key on the token from your template, instead of returning bytes.
- It produces the same keys as the BCL's `SP800108HmacCounterKdf` for the same inputs, so a key derived
  on the token can be re-derived in software from the same master key, if your design ever needs that.
- The default policy accepts HMAC with SHA-256 or stronger, and refuses the byte-returning overloads (see
  [Key derivation](key-derivation.md)).
